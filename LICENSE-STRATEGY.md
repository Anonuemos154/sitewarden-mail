# License strategy

Recommended public-launch model:

## Code
**AGPL-3.0-or-later** for the main application and service components, after legal review.

Why:
- keeps the software genuinely free/open;
- discourages closed hosted forks from taking improvements private;
- still allows commercial use;
- supports a later dual-licensing business model if every relevant copyright holder has assigned
  or licensed the necessary rights to the project owner.

## Commercial license
Offer a separate commercial license to companies that want to embed/modify the code without AGPL
obligations.

## Trademark
Open-source code does not mean the brand is free to impersonate. Keep the SiteWarden/MSD names,
logos and official signing identity under a separate trademark policy.

## Important
Do not casually mix third-party dependencies whose licenses are incompatible with the chosen
license. Add automated license scanning before public releases.

This repository intentionally does not pretend the licensing decision is final. Obtain legal
review before launch.
